# Running the GPU evaluation on RunPod

`scripts/run_a100.sh` does the whole Part A run on one GPU: it writes `results/env.json`, runs the test suite with real Triton, runs the kernel benchmark, runs the Hugging Face eval sweeps on Qwen3-8B (vault, then ALFWorld if it installs cleanly), summarizes everything with sample sizes and confidence intervals, and regenerates the README's results section from those files. Its hour budgets add up to about 4 GPU hours, plus setup and the model download.

## 1. Rent a pod

1. On [runpod.io](https://www.runpod.io), go to **Pods → Deploy**.
2. Pick an **A100 80GB** (SXM or PCIe). Another 80 GB GPU works too; the README records which GPU produced the results.
3. Template: **RunPod PyTorch** (any recent CUDA 12 version).
4. Disks: container disk **50 GB**, volume disk **100 GB** mounted at `/workspace`. The volume survives a stop, so the model cache and the results do too.
5. Deploy, then open a terminal: **Connect → Web Terminal**, or SSH.

## 2. Run

```bash
cd /workspace
git clone https://github.com/Maurya30/actkv-open && cd actkv-open
export HF_HOME=/workspace/hf              # keep the ~16 GB model download on the volume
tmux new -s run                           # keeps running if your connection drops (reattach: tmux attach -t run)
bash scripts/run_a100.sh 2>&1 | tee -a run.log
```

The script installs the package with `.[triton,dev,eval]` into the pod's Python, so no separate setup is needed. Qwen3-8B is not gated, so no Hugging Face token is needed.

Progress is printed after every task: time used, time per task and an ETA. If the pod restarts or you stop the script, run the same command again. Finished steps are skipped, and the sweeps continue from the last finished episode, counting the time already spent against their budgets.

Knobs (environment variables):

| variable | default | meaning |
|---|---|---|
| `HOURS_VAULT` | 2.75 | time budget for the vault sweep |
| `HOURS_ALFWORLD` | 0.75 | time budget for the ALFWorld sweep (added to vault if ALFWorld doesn't install) |
| `ALFWORLD` | 1 | `0` skips ALFWorld |
| `N_TASKS` | 50 | upper bound on vault tasks; the budget usually stops the sweep first |
| `MODEL` | Qwen/Qwen3-8B | any Hugging Face causal LM with full-attention layers |

To check the pipeline without a GPU first, run `bash scripts/run_a100.sh --dry-run` on any machine. It uses a tiny random model in a temp dir and deletes it afterwards.

## 3. What you get

```
results/env.json                 GPU, driver, versions, git commit
results/pytest.txt               test output (kernel tests must have run, not skipped)
results/bench_kernels.json/.txt  kernel benchmark, with measured memory
results/vault/*.jsonl            one line per episode, one file per config
results/vault/summary.json/.txt  per-config tasks, accuracy with 95% CI, paired delta vs FullKV
results/vault/pareto.png         accuracy vs peak KV memory
results/alfworld/...             the same, if ALFWorld ran
README.md                        results section regenerated by scripts/update_readme.py
```

## 4. Bring the results back

**Option A, commit on your Mac (no credentials on the pod).** On the pod:

```bash
tar czf /workspace/results.tgz results README.md
runpodctl send /workspace/results.tgz     # prints a one-time code
```

On your Mac (install `runpodctl` from RunPod's docs first), from the repo: `runpodctl receive <code>`, then `tar xzf results.tgz`, check the diff, and commit and push as usual.

**Option B, commit on the pod.** Create a fine-grained GitHub token limited to this repository with *Contents: read and write*. Then:

```bash
git config user.name "Maurya Panchal" && git config user.email "m25panch@uwaterloo.ca"
git add results README.md && git commit -m "results: A100 run"
git push https://Maurya30@github.com/Maurya30/actkv-open.git main   # paste the token as the password
```

## 5. Stop paying

In the RunPod console, under **Pods**:

- **Stop** ends GPU billing. The volume (model cache, results) stays and is billed as storage until you terminate.
- **Terminate** deletes the pod and its volume, and all billing stops. Copy the results off first.

The pod keeps billing while it is running, even if the script has finished, so stop it as soon as the run is done.
